### 1.5 Wide-Open CORS & Spoofable Rate-Limit Bypass
* **Credentialed CORS Reflection**: [server.ts](file:///Users/jeevanriship/AI%20WhatsApp%20Sales%20Agent/apps/api/src/server.ts#L48-L57) sets `origin: (_origin, cb) => cb(null, true)` combined with `credentials: true`. Any malicious third-party website visited by an authenticated shopper can perform cross-origin authenticated `GET`/`POST`/`PATCH`/`DELETE` calls to checkout, cancel orders, exfiltrate order history/addresses, or mutate carts.
* **Header-Spoofable Rate Limiting**: [server.ts](file:///Users/jeevanriship/AI%20WhatsApp%20Sales%20Agent/apps/api/src/server.ts#L26-L63) enables `trustProxy: true` globally alongside `allowList: ['127.0.0.1', '::1', 'localhost']`. Even worse, global rate limit uses in-memory storage (default in `@fastify/rate-limit` when no Redis instance is passed), so across multi-replica deployments limits don't coordinate, and any attacker can bypass limits by sending `X-Forwarded-For: 127.0.0.1` when proxies don't strip/overwrite untrusted headers.

### 1.6 Dashboard Middleware Dot-Bypass & Auth Error 500s
* **Dot-Segment Auth Bypass**: [apps/dashboard/src/middleware.ts](file:///Users/jeevanriship/AI%20WhatsApp%20Sales%20Agent/apps/dashboard/src/middleware.ts#L33) uses `pathname.includes('.')` to skip JWT checks for static files. Any future API route containing a dot (e.g., `/api/export.csv` or versioned endpoints) or dot-encoded segment completely bypasses edge authentication.
* **Unhandled `NEXT_REDIRECT` Caught as `500`**: Both [handoff/status/route.ts](file:///Users/jeevanriship/AI%20WhatsApp%20Sales%20Agent/apps/dashboard/src/app/api/handoff/status/route.ts#L8-L66) and [ai-agent-toggle/route.ts](file:///Users/jeevanriship/AI%20WhatsApp%20Sales%20Agent/apps/dashboard/src/app/api/settings/ai-agent-toggle/route.ts#L10-L61) invoke `getSession()` (which calls Next's `redirect('/login')`, throwing `NEXT_REDIRECT`) inside a broad `try/catch`, returning HTTP `500` instead of `401` when unauthenticated.

### 1.7 Customer Authentication Weaknesses
* **Concurrent OTP Brute-Force Race**: [`verifyOtp`](file:///Users/jeevanriship/AI%20WhatsApp%20Sales%20Agent/apps/api/src/services/customer-auth-service.ts#L161-L193) performs a non-atomic `redis.get` -> increment `otpData.attempts` in JS -> `redis.set`. ## 2. Financial, Payment Gateway & Webhook Exploits (`P0`)

### 2.1 Unauthenticated Production Payment Bypass (`/simulate`) & Live Outage Fallback
* **Free Order Marking in Production**: [server.ts](file:///Users/jeevanriship/AI%20WhatsApp%20Sales%20Agent/apps/api/src/server.ts#L86-L87) unconditionally mounts [`checkoutPaymentRoutes`](file:///Users/jeevanriship/AI%20WhatsApp%20Sales%20Agent/apps/api/src/routes/payments/checkout.ts#L7-L503) and [`phonePeCheckoutRoutes`](file:///Users/jeevanriship/AI%20WhatsApp%20Sales%20Agent/apps/api/src/routes/payments/phonepe-checkout.ts#L18-L451) in every environment with **zero authentication and zero `NODE_ENV` guard**. Anyone who knows or enumerates a UUID `orderId` can POST to `/payments/checkout/:orderId/simulate` or `/payments/checkout/phonepe/:orderId/simulate` and mark unpaid orders `PAYMENT_CONFIRMED` for free.
* **Outage Silently Routes Live Customers to Free Simulator**: In [`PhonePeService.createPaymentLink`](file:///Users/jeevanriship/AI%20WhatsApp%20Sales%20Agent/packages/payments/src/phonepe.ts#L203-L242) and [`RazorpayService.createPaymentLink`](file:///Users/jeevanriship/AI%20WhatsApp%20Sales%20Agent/packages/payments/src/razorpay.ts#L163-L210), **even when live production merchant keys are present**, any gateway timeout, HTTP 4xx/5xx error, or network hiccup silently falls back (`isSandboxMock: true`) to generating the local `/payments/checkout/...` simulator URL — handing real customers a 1-click free-payment button on WhatsApp!
* **Cross-Tenant Dashboard Simulator Escalation**: [`simulateRazorpayPaymentAction`](file:///Users/jeevanriship/AI%20WhatsApp%20Sales%20Agent/apps/dashboard/src/lib/actions/orders.ts#L246-L276) calls the unauthenticated Fastify endpoint `POST ${apiUrl}/payments/checkout/${orderId}/simulate` at [L258](file:///Users/jeevanriship/AI%20WhatsApp%20Sales%20Agent/apps/dashboard/src/lib/actions/orders.ts#L258) *before* ever checking `tenantId` ownership at [L274](file:///Users/jeevanriship/AI%20WhatsApp%20Sales%20Agent/apps/dashboard/src/lib/actions/orders.ts#L274), enabling any logged-in staff member of Tenant A to mark orders paid across any Tenant B.
